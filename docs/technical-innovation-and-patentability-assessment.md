# RAG 项目技术创新与可专利性汇报

更新时间：2026-05-09

> 说明：本文为项目技术创新与可专利性的内部汇报材料，侧重管理判断与申报方向，不构成正式法律意见。

## 1. 结论摘要

本项目不只是业务层面的应用封装，已经在 RAG 检索管线、数据处理流程、多模态上下文组装和系统鲁棒性方面形成了较完整的技术设计。

总体判断如下：

- 有实质性的技术改进，不属于单纯“模型接线”
- 创新主要体现在系统方法、检索策略和数据处理流程
- 目前未体现自研基础模型或底层索引算法创新
- 具备一定专利包装空间，适合围绕“方法 + 系统”进行申报准备

一句话概括：

**这是一个具备明确工程创新价值的 RAG 系统方案，创新点更偏检索与数据流程，而不是基础算法发明。**

## 2. 主要技术创新

### 2.1 检索策略创新

项目在传统向量检索基础上，形成了更完整的混合检索链路，核心价值包括：

- 对初始候选结果进行放大召回后再重排
- 将语义相关性与词法相关性融合，提升排序稳定性
- 识别文档间引用关系，触发跨文档二次检索
- 对多轮会话中的已使用内容进行去重，减少冗余上下文

这类创新直接作用于召回完整性、排序质量和多轮问答效果，属于典型的技术实现改进。

### 2.2 数据处理流程创新

项目在文档预处理和入库流程上做了较多面向实际场景的优化，核心价值包括：

- 面向混合文档结构的自适应分块，而非简单按固定长度切分
- 对重复内容、过短内容和结构噪声进行过滤与合并
- 为检索片段补充标题、关键词、时间、分类等增强信息
- 建立图文关联关系，支持后续多模态问答使用
- 对扫描件或抽取质量差的文档引入 OCR 回退

这类创新提高了数据质量、检索可用性和多模态协同能力。

### 2.3 多模态上下文创新

项目没有采用“全量带图”的粗放方式，而是将图片注入与检索证据绑定，核心价值包括：

- 仅在文本命中相关证据时才引入关联图片
- 控制图片注入数量，避免上下文失控
- 使多模态输入更有针对性，减少无关干扰

这类设计有利于提升模型利用外部证据的有效性，也更容易形成可论证的技术效果。

### 2.4 系统鲁棒性创新

项目在向量化与存储链路上也做了明显增强，核心价值包括：

- embedding 生成与向量库存储分批控制
- 写库失败时具备重试与恢复能力
- 对外部依赖异常具备降级和容错设计

虽然这部分更偏工程可靠性，但组合起来仍然具有较强的系统价值。

## 3. 是否属于“底层技术创新”

从严格意义上说，本项目目前的创新不属于“基础算法或模型层创新”，主要原因是：

- 未见自研 embedding 模型
- 未见自研向量索引或 ANN 结构
- 未见自研学习式 reranker 模型
- 未见对 LLM 或 OCR 模型结构本身的训练与改造

因此，本项目更适合定义为：

- **RAG 系统方法创新**
- **检索与重排流程创新**
- **文档处理与多模态协同创新**
- **稳定性与可用性工程创新**

不建议对外表述为“原创底层算法”或“自研核心模型算法突破”。

## 4. 可专利性的工程价值判断

从专利角度看，本项目具备一定可包装性，原因在于其创新点并非停留在抽象规则层面，而是围绕实际技术对象和系统流程展开，且能够对应到较清晰的技术效果，例如：

- 提高检索准确率和证据覆盖率
- 降低多轮对话中的冗余上下文
- 提高图文混合文档的解析完整性
- 降低重复向量与无效碎片
- 提高大批量入库场景下的稳定性与成功率

因此，项目具备“专利工程化包装”的基础。

但也要明确：

- 这不等于必然满足授权条件
- 如果缺少现有技术对比和实验数据，很多亮点仍可能被认定为常规拼装
- 单独拆开的细小技巧通常不够强，组合式方案更有申报价值

## 5. 最值得申报的方向

结合现有实现成熟度和可包装性，建议优先考虑以下两个方向。

### 方向一：跨文档引用感知的混合检索方法

这是当前最值得优先包装的方向。

建议主打价值：

- 面向规范类、制度类、知识库类文档
- 结合语义召回、词法重排和跨文档关联发现
- 解决单轮检索无法充分覆盖关联证据的问题

预期技术效果：

- 提升关联文档召回完整性
- 提高答案证据覆盖率
- 降低因漏召回导致的回答偏差

### 方向二：面向图文混合文档的自适应切分与关联入库方法

这是第二个较强的申报方向。

建议主打价值：

- 面向图文混排、结构不整齐、质量参差不齐的知识文档
- 通过清洗、分块、去重、增强和图文关联，形成更适合检索与问答的数据表示

预期技术效果：

- 提高 chunk 完整性
- 减少重复和无效向量
- 改善多模态问答的数据基础

## 6. 可作为补充申报或从属方案的方向

除上述两条主线外，以下方向也有工程价值，但更适合作为从属方案或后续补充申报：

- 会话级上下文去重与增量上下文构建
- 按检索证据触发的图片注入方法
- 向量化批处理与写库容错方法

这些点单独申报时创造性压力更大，但与主线组合后价值会明显增强。

## 7. 不建议单独主打的点

以下内容不建议作为单独的核心专利点：

- 单独的 BM25 评分
- 单独的分数归一化加权
- 单独的关键词抽取
- 单独的简单分类规则
- 单独的 OCR 兜底

原因是这些点过于常见，容易被认定为通用算法、经验规则或常规工程处理。

## 8. 当前最大的短板

如果项目后续希望真正具备较强的专利申报基础，当前最大的短板不是“缺功能”，而是“缺证据”。

建议尽快补齐以下对比证明：

- 混合检索相对纯向量检索的效果提升
- 跨文档二次检索相对普通检索的效果提升
- 自适应分块相对固定切块的效果提升
- 会话级去重对上下文冗余和推理成本的改善
- 容错写库对稳定性和成功率的改善

没有这些量化结果，很多亮点只能停留在“工程上合理”，难以上升到“可证明的技术效果”。

## 9. 建议动作

建议按以下顺序推进：

1. 先明确主申报方向，优先在“跨文档引用感知混合检索”和“图文混合文档自适应入库”之间选主线
2. 补做 A/B 对比实验，形成可量化指标
3. 将次级创新点整合进主方案，避免碎片化申报
4. 再由专利代理师据此撰写方法、系统、存储介质和程序产品四套权利要求

## 10. 最终判断

从内部汇报角度可以给出如下结论：

**本项目已经具备可被认定为“技术改进”的工程创新基础，且存在较明确的专利包装方向。**

其中：

- **最强创新主线**：跨文档引用感知的混合检索方法
- **第二创新主线**：面向图文混合文档的自适应切分与关联入库方法
- **辅助创新点**：会话级去重、证据驱动的图片注入、写库容错

如果后续补足实验和现有技术对比材料，这个项目具备进一步沉淀为专利交底材料的价值。
